# Reporting security issues

Report a suspected vulnerability privately before sharing details in public issues, PRs or screenshots.

## Reporting route

If the repository's Security tab offers **Report a vulnerability**, use that private form. Otherwise contact Commander Chara at [@cmdr_chara on X](https://x.com/cmdr_chara) by direct message if available, or use an existing private channel with the maintainer. If you cannot reach a private channel, request one on X or open a minimal GitHub issue; do not include the vulnerability, exploit, affected personal data or credentials in that public request.

The presence of this policy does not mean GitHub private vulnerability reporting is enabled or that the app has passed a security audit.

## Useful information

- App version/build or commit, platform/OS and relevant device details.
- The affected feature, expected security boundary and observed impact.
- Minimal reproduction steps or a proof of concept that avoids accessing other people's data.
- Whether the issue affects the current `main` branch, if you were able to check safely.

Redact tokens, API secrets, account details, file paths and personal media. Do not upload full music libraries, backups or unlicensed third-party material. Use synthetic fixtures where possible.

Maintainers will assess reports against the current code and coordinate follow-up through the agreed private channel. This project does not promise a response deadline, bounty or support window for every older build.

Regular bugs and feature requests belong in the [issue templates](https://github.com/cmdr-chara/Songlass/issues/new/choose). Conduct concerns follow the [Code of Conduct](CODE_OF_CONDUCT.md#reporting-a-concern).
